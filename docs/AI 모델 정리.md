# AI 모델 전체 정리

`callwrap_ai` 패키지는 `analyze(transcript) -> AnalysisResult` 함수 하나만 외부에 노출하는 무상태(stateless)
라이브러리다. 통화 전사 하나를 넣으면 F1~F4 판정이 한 번에 채워져 나온다. 모든 판정은 동일한 구조를 공유한다.

```
Judgment[T] = { value: T, confidence: float, evidence_indices: int[] }
```

기관 실데이터는 반출이 불가능해서, 2026-07-29 3자 회의에서 데이터 확보를 3단계로 정했다.
**현재 모든 모델은 1단계(생성) 데이터로만 학습·평가된 상태**다 — 아래 지표는 전부 이 전제로 읽어야 한다.

1. 생성 — FAQ → 시나리오 → TTS 합성 (← 현재 위치)
2. 검증 — 공개 실음성 데이터
3. 확장 — 기관 가명처리 실데이터 (확보 시)

## 한눈에 보기

| 기능 | 모델 | 방식 | 핵심 지표 | 상태 |
|---|---|---|---|---|
| F2 | 중분류 (6종) | klue/roberta-base 파인튜닝 | Macro-F1 0.4637 (목표 0.85) | 연결됨 |
| F2 | 소분류 (29종) | klue/roberta-base + 중분류 마스킹 | Macro-F1 0.34~0.46 | 연결됨 |
| F2 | 상담유형(SR유형, 8종) | klue/roberta-base + 화자임베딩 + 멀티라벨 | Macro-F1 0.883 (val 14건) | 연결됨 |
| F3 | 상담등급(칭찬/악성/일반) | EXAONE 3.5 7.8B + 2축 규칙 | 악성 Recall 0.963 | 연결됨 |
| F1·F4 | 요약·후속처리·FAQ필요 | EXAONE 3.5 7.8B 프롬프트 | 공식 성능표 없음 | 지표 미정량화 |

## 1. 중분류 (F2, 6종) — `category-klue-roberta-base-seed42`

**목적**: 상담분류 계층(대분류=장애인활동지원 고정 > 중분류 6종 > 소분류 29종)에서 중분류를 단일 라벨로
분류. 결제및비용지급 / 대상자관리 / 부정사용 / 제공기관관리 / 제공인력관리 / 지자체사업관리 6종. 명세상
성능 목표(Macro-F1 ≥ 0.85)가 걸린 주 지표.

**아키텍처**: `klue/roberta-base` 파인튜닝, `AutoModelForSequenceClassification`(6-way softmax). 512토큰
상한, 인사말 제거 전처리를 학습·추론이 공유.

**학습법**:
- 10 epoch · lr 2e-5 · batch 8, seed 42/7/2026 3회 반복
- MPS(Apple Silicon) fp32 — fp16은 MPS에서 불안정해 배제
- 마지막 에폭 채택(조기 종료 안 함 — 검증 20건 과적합 위험 때문)
- 20 epoch 시 val Macro-F1 0.4159로 하락 확인 → 10 epoch 채택

**학습 데이터**: 기관 FAQ 333건에서 생성한 상담 시나리오를 Claude·Gemini 교차 라벨링(일치 74건 + 사람
검수 26건) — 총 100건. 부정사용(9건)이 최소 클래스라 무작위 분할 대신 계층 분할(stratified) 80/20 채택.
클래스 분포: 대상자관리 31 · 제공기관관리 17 · 결제및비용지급 16 · 제공인력관리 14 · 지자체사업관리 13 ·
부정사용 9.

**지표** (seed 3회 평균, 검증 20건 기준):

| 구분 | Macro-F1 | Accuracy |
|---|---|---|
| seed 42 | 0.4991 | 0.500 |
| seed 7 | 0.4429 | — |
| seed 2026 | 0.4492 | — |
| **평균 ± 표준편차** | **0.4637 ± 0.0251** | 0.4833 |

> ⚠️ **목표 대비 미달**: "목표는 명세 7장의 Macro-F1 ≥ 0.85다. 크게 미달이며, 원인은 모델이 아니라 데이터
> 부족이다. 학습 데이터가 80건, 클래스당 7~25건뿐이다." (train/README.md) — 6클래스 무작위 추측 기준선
> ≈ 0.17이므로 절대적으로는 유의미하게 학습된 상태.

**상태**: 학습 완료, 파이프라인에 연결됨(2026-08-18). 지표는 대외 인용 금지.

## 2. 소분류 (F2, 29종, 보조 출력) — `subcategory-klue-roberta-base-seed42`

**목적**: 소분류 29종 분류. 명세상 보조 출력이며 성능 목표는 중분류에만 걸려 있다. 추론 시 예측된(또는
주어진) 중분류에 속한 소분류만 후보로 남기고 그 위에서 재정규화하는 **계층 마스킹**을 적용(비후보 클래스
로짓을 −∞로 만들고 argmax).

**아키텍처**: 중분류와 같은 계열 `klue/roberta-base`, 29-way softmax + 추론 시 중분류 마스킹.

**학습법**: 10 epoch · lr 2e-5, seed 42/7/2026. 학습 146건 / 검증 37건.

**학습 데이터 — 총 183건**: 확정 골든셋 93건(사람검수 11 + 검수전 초안 82) + 증강 90건. 증강분은 0건이던
클래스를 채우는 용도로만 생성(교통비지급 / 기타 / 바우처생성 / 본인부담금환급 / 캡방식 등 5종 포함, 전
29종에 검증 1건 이상 확보).

TF-IDF 누출 진단: 신규90건 0.219 · 기존93건 0.273 · 합본183건 0.370 (모두 정상, 0.95 넘으면 누출 의심 —
참고로 SR유형 1차 생성 60건은 1.000이 나와 폐기된 전례가 있다).

**지표** (Macro-F1, seed 3회):

| 조건 | seed42 | seed7 | seed2026 | 평균 |
|---|---|---|---|---|
| 마스킹 없음(29지선다) | 0.3092 | 0.4023 | 0.4092 | 0.3736 |
| 정답 중분류 마스킹(모델 자체 실력 상한) | 0.3874 | 0.4989 | 0.5046 | **0.4636 ± 0.0661** |
| 예측 중분류 마스킹(실서비스 조건) | 0.2874 | 0.3783 | 0.3615 | 0.3424 ± 0.0484 |

> ⚠️ **이중 병목**: "중분류를 아무리 개선해도 소분류는 0.4636을 넘지 못한다(정답 마스킹 점수가 상한).
> 그 위는 소분류 데이터를 늘려야 한다." (train/README_subcategory.md)
>
> ⚠️ **실서비스 적용 시 미결 사항**: 예측 중분류 마스킹(0.3424)이 마스킹 없음(0.3736)보다 오히려 낮다 —
> 중분류가 틀리면 정답 소분류가 후보에서 통째로 빠지기 때문. "실서비스에서 마스킹을 그대로 걸면 안 된다"는
> 지적만 있고, 완화 방식은 아직 정해지지 않았다(TODO).

**상태**: 학습 완료, 파이프라인 연결됨(`classify.predict_subcategory` + `pipeline.py`의 `_check_hierarchy`
안전망). 마스킹 운용 방식은 미결.

## 3. 상담유형/SR유형 (F2, 8종, 멀티라벨) — `sr-type-klue-roberta-base-v2`

소유: 이재혁 — 별도 하위 프로젝트 `src/model_SR/` ("B안").

**목적**: 사용법문의 / 자료확인 / 자료보정 / 시스템오류 / 정책 및 지침문의 / 기능개선 / 고객PC환경 / 기타
8종 중 최종 1종을 판정. 적기처리기간(1~30일)이 라벨마다 달라, "이 건이 어디로 가서 어떻게 처리되는가"
기준으로 라벨링된다.

**아키텍처**:
- 백본 → 풀링(CLS+mean 결합) → dropout → Linear → **8-way sigmoid**(멀티라벨, softmax 아님)
- 화자 임베딩 `nn.Embedding(2, hidden)`을 토큰 임베딩에 더함, **0으로 초기화**(학습 초기엔 항등,
  RoBERTa는 `type_vocab_size=1`이라 세그먼트 임베딩을 못 써서 이 방식 채택)
- 발화별 `[상담사]`/`[고객]` 스페셜 토큰(vocab 32000→32002)
- 512토큰 초과 시 head+tail 절단
- 배포 checkpoint의 실제 백본은 `klue/roberta-base`(가이드가 권장하는 large는 300건 이상용 — 데이터가
  적어 base로 감을 잡은 것으로 보임)

**학습법**:
- `BCEWithLogitsLoss` + 우선순위 가중(pos_weight) + 클래스 불균형 보정
- AdamW + Layer-wise LR Decay(0.9) + head_lr_mult 10 + linear warmup 10%
- bf16 autocast + TF32, **RTX 4080 SUPER 16GiB**(전체 프로젝트 중 유일한 CUDA 학습 — 나머지는 MacBook MPS)
- STT 노이즈 증강(문장부호 제거·filler·자기수정·화자 뒤집힘 등) 매 epoch 재샘플
- epoch 1~18 중 **epoch 12** 채택(train loss ≈ 0.26)

**추론 시 후처리 — 우선순위 축약**: 임계값을 넘은 라벨들 중 적기처리기간이 긴 항목 우선 규칙으로 하나만
선택한다: 시스템오류 > 기능개선(둘 다 30일, 업무중단 우선) > 자료보정 > 정책 및 지침문의(둘 다 5일,
쓰기작업 우선) > 고객PC환경 > 자료확인 > 사용법문의 > 기타(fallback).

**학습 데이터 — 학습 98건 / 검증 14건 (총 112건)**: 콜드 컨텍스트 서브에이전트 4개 병렬 생성(28건×4).
"라벨 먼저 정하고 대화 생성" 방식, 생성 격자 = SR유형(8) × 업무소분류(29) × 난이도(일반50%/경계30%/복합20%).
1차 직접 생성 60건은 TF-IDF 베이스라인 macro-F1이 **1.000**이 나와 폐기(표현을 외운 신호) — 최종 데이터는
0.6375(정상범위 0.55~0.90).

도메인 코퍼스(전자바우처·장애인활동지원·세종시 FAQ 201건, 43,453자)를 수집했으나 **DAPT는 생략** — MLM
도메인 적응에 필요한 양(수 MB)에 크게 못 미쳐서다.

**지표** (검증 14건 기준, checkpoint `config.json`):

| 지표 | 값 |
|---|---|
| Macro-F1 (epoch 12, 채택 시점) | **0.8833** |
| SLA 위반율 | 0.0769 |

> ⚠️ **캘리브레이션 미완**: "받은 checkpoint의 임계값은 아직 전부 0.5(초기값)이고, 검증셋도 14건이다.
> 3-tier UI 임계값에 물리기 전 보정이 필요하다." (`src/callwrap_ai/sr_type.py`)
>
> ⚠️ **실데이터 검증 대기**: 실데이터 테스트셋(200~300건)은 가명처리 대기 중이며, "합성 검증셋 지표는
> 낙관적이다"라고 문서에 명시. 100문100답 PDF 미확보로 실코퍼스 기준 소분류 29종 중 16종은 커버리지 0건.

**상태**: 학습 완료, 파이프라인 연결됨(2026-08-20). 임계값 캘리브레이션·실데이터 검증은 미완.

## 4. F3 상담등급 (칭찬콜/악성콜/일반) — EXAONE 3.5 7.8B + 2축 규칙

**목적**: 통화 전체를 3등급으로 판정. **악성콜 감지가 최우선 목표** — 놓치면 다시 발견할 기회가 없지만,
오탐은 상담사 검토로 걸러지므로 비대칭 손실을 그대로 인정한다.

**방법 — 파인튜닝이 아니라 LLM 감정채점 + 규칙**: 발화 단위 감정 정답이 없어(가진 건 통화 단위 등급 라벨
186건뿐) 전용 모델 파인튜닝이 애초에 불가능했다. 대신 통화당 EXAONE 1회 호출로 민원인 발화별 감정 점수
(−1~1)를 얻고, **2축 규칙**으로 매핑한다(임계값은 코드가 아니라 `grade_rule.json`으로 분리):

```
score_min  < -0.70  (통화 중 가장 격한 발화)     → 악성콜
score_tail >  0.75  (통화 후반 1/3 평균)         → 칭찬콜
그 외                                            → 일반
```

**모델 선정 — 183건 5-fold 교차검증 3방식 비교**:

| 방식 | 파라미터 | 라이선스 | Macro-F1 | 악성 Recall |
|---|---|---|---|---|
| Gemma 3 | 12B | Gemma Terms(상업가능) | 0.7191 | 0.8148 |
| **EXAONE 3.5 (채택)** | 7.8B | NC(비상업) | 0.6727 | **0.8519** |
| 전용 감정모델(KoELECTRA) | 0.11B | MIT | 0.4516 | 0.5185 |

Macro-F1은 Gemma가 0.05 앞서지만 최우선 지표인 악성 Recall은 EXAONE이 높고, 처리 3.9초 vs 7.4초(약 2배
빠름), 국산 온디바이스(보안·데이터 미유출)라 EXAONE을 채택했다. Qwen 등 중국 모델은 국가기관 도입 불가
방침으로 후보에서 제외됐다.

**학습/평가 데이터 — 186건**: 일반 132 · 악성콜 28 · 칭찬콜 26 (원본 골든셋 96 + 소분류 증강 부산물 90건이
최소클래스를 16→26건으로 보강). `(욕설)`·`(한숨)` 표지 27건은 전부 악성콜에만 붙어 있어 채점 전 제거
(표지 유무 차이는 0.01뿐 — 어조가 문장 자체에 남아있음을 확인).

**최종 채택 규칙(2축) 성능**:

| 등급 | Precision | Recall | F1 | 건수 |
|---|---|---|---|---|
| 악성콜 | 0.96 | **0.96** | 0.96 | 27 |
| 일반 | 0.88 | 0.92 | 0.90 | 131 |
| 칭찬콜 | 0.47 | 0.36 | 0.41 | 25 |
| **전체** | — | — | **Macro-F1 0.7559** | Accuracy 85% |

**처리 시간** (MacBook Pro M5·32GB 기준): 통화 1건 감정분석 4.03초 · `analyze()` 전체 3.70초. 186건 전체는
EXAONE 719초(12분) vs Gemma 1383초(23분). 기관 연간 34만 건(하루 약 930건) 기준 **하루치를 노트북 한 대로
약 1시간에 처리** 가능(배치 처리 전제).

> ⚠️ **라이선스**: "비상업(NC)이다. 실증 단계에서는 쓸 수 있으나 실제 도입 시 교체 검토가 필요하다.
> 발표에서 '이 모델로 도입 가능하다'고 말하지 않는다. Gemma 3는 상업 이용이 가능해 도입 시 대안이 된다."
>
> ⚠️ **라벨 미검수**: 등급 라벨 186건은 전부 사람 검수 전(생성 시점 값 + LLM 초안)이다. 칭찬콜 25건 중
> 16건이 일반으로 흘려지는 것도 현재는 감수 중인 트레이드오프 — 감정 점수만으로는 "상담사를 향한 평가"라는
> 내용 신호를 못 잡는다.

**상태**: 채택 및 파이프라인 연결 완료.

## 5. F1 요약 / F4 후속처리 필요 / FAQ 필요 — EXAONE 3.5 7.8B 프롬프트

**목적**: 통화당 EXAONE 1회 호출로 세 가지를 동시에 산출한다 — 요약(제목/문의내용/처리내용), 후속처리
필요 여부, FAQ 등록 필요 여부. **파인튜닝이 아니라 프롬프트 엔지니어링**이다.

**프롬프트** (v1~v6, 현재 v6):
- 화자 혼입 금지 — 문의내용=고객만 / 처리내용=상담사만
- "누가·왜·무엇을" 순서 서술, 완결문장 강제
- 분량 규칙: 제목 20자 · 문의 80~90자 · 처리 100~150자
- 후속처리 필요=true는 "상담사가 실제로 약속한 문장이 있을 때만"
- FAQ 필요=true는 "누가 물어도 같은 답이 나오는" 일반화 가능한 문의만

**확신도(confidence) 산출**: LLM 자기보고가 아니라 Ollama `logprobs`가 주는 토큰 확률의 기하평균에서
뽑는다. 예전엔 confidence가 0.0으로 고정돼 있어 3-tier UI의 "high 원클릭 승인"이 한 번도 뜨지 않던 문제가
있었다(2026-08-20 수정).

**평가 데이터·방식**: `summary_dataset.jsonl`, `summary_gold_v2.jsonl`이 존재하고 `eval_summary.py`가
ROUGE-1/2·재현율·평균길이·bool Acc/F1을 출력한다. 다만 **ROUGE는 참고용일 뿐**("요약은 정답이 하나가
아니라 n-gram 겹침으로는 품질을 다 못 잰다") — 실제 목적은 화자 혼입/내용 누락/분량 이탈/bool 오답 같은
실패 유형을 자동 탐지하는 것이다.

> ⚠️ **정량 지표 없음**: 채택된 v6 프롬프트의 최종 성능 수치(정확도·F1 등)를 명시한 공식 리포트 파일은
> 저장소에 없다. 파이프라인에는 연결되어 실제로 동작하지만(2026-08-18 전환), 목표 대비 달성 여부를 보여주는
> 성능표는 아직 없다.
>
> ⚠️ **확신도 해석 주의**: "캘리브레이션된 정확도 확률이 아니다. 토큰 확률은 '이 문장을 이렇게 쓸
> 확신'이지 '이 판정이 맞을 확률'이 아니다." logprobs 미지원 구버전 Ollama에서는 0.0으로 떨어진다.

**상태**: 파이프라인 연결·동작, 정량 성능표는 없음.

## 6. FAQ 배치 생성 (부속 기능)

`needs_faq=true`로 쌓인 통화들을 소분류 단위로 모아 EXAONE에 한 번에 넘겨 대표 질문·답변을 합성한다.
FastAPI의 `POST /internal/faq/generate-batch`가 호출한다. 모델은 F1과 동일한 EXAONE, 파인튜닝 없음, 전용
프롬프트(`faq_v1.md`) 사용. 별도 지표 문서는 없다.

## 7. 검토 후 미채택 — 전용 감정분석 모델 (KoELECTRA)

상담등급(F3) 후보로 5-fold 비교에 포함됐으나(Macro-F1 0.4516, 악성 Recall 0.5185) 최종 탈락했다. 저장소에
이 모델의 학습된 checkpoint는 존재하지 않는다 — 비교 실행용 스크립트만 남아 있다.

> ⚠️ **탈락 사유**: "무감정 클래스가 없어 중립 문의도 angry 0.874로 쏠린다." 예: "제공기관 정보를 어디서
> 확인하면 되는지 알고 싶어요" → KoELECTRA는 angry 0.874(오답)인데 EXAONE/Gemma는 중립~긍정으로 올바르게
> 판단.

현재 감정 신호는 전부 EXAONE 프롬프트 출력에서 얻으며, 스키마에 별도 "감정분석 결과" 필드는 없다(F3 내부
중간값일 뿐).

## 8. 종합 캐비어트

1. **전 모델 공통**: "현재 지표(중분류 Macro-F1 0.50 · 소분류 0.31~0.39)는 재현 데이터 기준 내부 값이다.
   대외 발표·보고서 인용 금지. 파이프라인이 동작함을 확인하는 용도이며, 서비스 품질의 근거로 쓰지 않는다."
   (AI-model/README.md)
2. **라벨 검수 상태**: 중분류 골든셋을 제외한 대부분의 라벨(소분류·등급·SR유형 검증셋 일부)이 사람의 최종
   검수를 거치지 않은 생성 시점 값 또는 LLM 초안 상태다.
3. **스코프 오염 이력**: 소분류 학습 데이터에서 스코프 밖 항목(청소년산모·발달재활 등)이 발견되어
   제외됐다 — 같은 오염이 중분류 골든셋에는 아직 남아있을 가능성이 있다.
4. **EXAONE 라이선스**: F3(등급)·F1(요약)·F4(후속처리)·FAQ 필요·FAQ 배치생성까지 전부 EXAONE 3.5 7.8B에
   의존하는데, 이 모델은 비상업(NC) 라이선스다. 실제 서비스 도입 시점엔 상업 라이선스 모델(Gemma 3 등)로
   교체 검토가 필요하다.
