목표는 명세 7장의 **Macro-F1 ≥ 0.85**다. 크게 미달이며, **원인은 모델이 아니라 데이터 부족**이다.
학습 데이터가 80건, 클래스당 7~25건뿐이다. 이 규모에서 0.46은 예상 범위 안이며

seed를 바꿔도 편차가 ±0.025로 작다. 즉 **0.46은 운이 아니라 이 데이터로 낼 수 있는 실력**이고,
목표와의 격차도 재현성 있게 확인된 값이다.

## 2. 재현 방법

```bash
uv sync --extra train                                    # torch·transformers·sklearn

uv run --extra train python train/split_data.py          # 골든셋 100건 → 학습 80 / 검증 20
uv run --extra train python train/train_category.py      # 학습·채점·저장 (seed 42)

# seed 3회 (위 결과표 재현)
for s in 42 7 2026; do
  uv run --extra train python train/train_category.py --seed $s
done
```

산출물은 `data/` 아래라 커밋되지 않는다. 위 명령으로 재현한다.
- 분할: `data/scenarios/train.jsonl`, `data/scenarios/val.jsonl`
- 모델·지표: `data/models/category-{모델}-seed{시드}/` (`metrics.json`에 설정·에폭별 이력·최종 점수)

> 저장 경로에 에폭이 들어가지 않는다. **에폭만 바꿔 돌리면 앞 결과를 덮어쓴다.**
> 모델·seed를 바꾸는 비교는 경로가 갈리므로 안전하다.

## 2-1. 학습한 모델로 예측하기

`predict.py`는 저장된 checkpoint를 읽어 분류와 확신도를 출력한다. 추론만 하므로
모델은 바뀌지 않고, 같은 입력이면 항상 같은 결과가 나온다.

```bash
uv run --extra train python train/predict.py --file data/samples/demo.txt      # 대본 1건
uv run --extra train python train/predict.py --file data/samples/stt_demo.json # STT 출력 1건
uv run --extra train python train/predict.py --file data/scenarios/val.jsonl   # 배치·채점
uv run --extra train python train/predict.py --text "상담사: ...\n고객: ..."
```

입력 형식은 확장자로 구분한다.

| 확장자 | 내용 |
|---|---|
| `.txt` | 원본 대본 평문 — `화자: 발화`를 줄바꿈으로 이은 것 |
| `.json` | **STT(whisper) 출력** — `{"utterances": [{index, speaker, text, start, end, confidence}, ...]}` |
| `.jsonl` | 골든셋 배치 — 줄마다 예측하고 `category`가 있으면 채점 |

인사말 제거와 512토큰 절단은 학습 때와 동일하게 스크립트가 처리한다.

```
중분류            확신도
제공인력관리      0.321
대상자관리        0.296
제공기관관리      0.153
```

`.jsonl`을 주면 줄마다 예측한다. `category` 필드가 있으면 채점까지 해서 무엇을
무엇으로 착각하는지 보여준다 — 오류 분석용이다.

```
ID        예측             확신도  정답
v2-009    제공인력관리     0.321  O
scn-079   제공인력관리     0.399  X → 제공기관관리
...
20건 중 10건 정답 (0.500)
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--model-dir` | `data/models/category-klue-roberta-base-seed42` | checkpoint 경로 |
| `--top-k` | 3 | 단건일 때 보여줄 후보 수 |
| `--max-length` | 512 | 학습과 같은 값을 쓴다 |

라벨 순서는 checkpoint의 `config.json`(`id2label`)에서 읽는다. 계약(`schemas.py`)의
enum 순서가 바뀌어도 이미 학습된 모델은 자기 매핑을 그대로 쓰므로 어긋나지 않는다.

### STT 출력을 받을 때

whisper는 대략 문장 단위로 자르므로 한 사람이 이어 말한 내용이 여러 발화로 쪼개진다.
학습 대본은 한 턴이 한 줄이었으므로 `utterances_to_text()`가 **연속된 같은 화자 발화를
합친다.** 합치지 않으면 `상담사: `가 줄마다 붙어 512토큰을 화자 표기가 잡아먹는다.

화자 표기가 학습 데이터(`상담원`·`문의자`·`제공기관 담당자` 등 15종)와 STT 출력
(`상담사`·`고객` 2종)에서 다르지만, **검증셋 실측 결과 중분류 성능에 영향이 없어
재학습하지 않았다.** 모델이 화자 라벨이 아니라 본문으로 판단하고 있다.

| 입력 | 정확도 | 평균 확신도 |
|---|---|---|
| 원본 대본 (학습과 동일) | 0.500 | 0.421 |
| 화자를 STT 형식으로 정규화 | 0.500 | 0.418 |
| 화자 접두어 제거 | 0.500 | 0.415 |
| 문장 분할까지 거친 STT 경유 | 0.500 | — |

다만 개별 건은 흔들린다. STT 경유 시 20건 중 2건의 예측이 바뀌었고(하나는 정답→오답,
하나는 오답→정답) 총점만 같았다. 확신도가 0.3~0.6에 몰려 있어 근소한 차이로 순위가
뒤집히기 때문이다.

**ASR 오인식 내성**(글자를 무작위로 바꿔 본 대략적인 확인, seed 3회 평균)

| 글자 오류율 | 0% | 2% | 5% | 10% |
|---|---|---|---|---|
| 정확도 | 0.500 | 0.500 | 0.467 | 0.467 |

10%까지 망가져도 크게 무너지지 않는다. 다만 검증 20건 기준이라 이 차이는
노이즈 범위 안이며, 실제 STT 오인식은 무작위가 아니라 특정 용어에 몰리므로
(`소득 자료` → `소득차료`) 실데이터에서 다시 확인해야 한다.

> 전처리는 `preprocess.py`를 **import**해서 쓴다. 복제하면 학습과 추론의 입력이
> 갈라져 예외 없이 결과만 틀린다. 검증셋 정확도가 `metrics.json`의 값과 일치하는지가
> 이 경로가 맞게 이어졌는지 확인하는 방법이다.

## 4. 설정값과 근거

| 인자 | 기본값 | 근거 |
|---|---|---|
| `--model` | `klue/roberta-base` | 명세 8.2·Step 3. KLUE 벤치마크에서 안정적 |
| `--seed` | 42 | 재현성. 여러 개로 돌려 편차 측정 |
| `--max-length` | 512 | roberta 구조상 상한 |
| `--epochs` | 10 | 아래 실측 |
| `--lr` | 2e-5 | 이 계열 관례값 |
| `--batch-size` | 8 | 80건 기준 1에폭 = 10스텝 |

디바이스는 MPS(Apple Silicon), fp32. MPS에서 fp16은 불안정하다(명세 11장).

**에폭 10의 근거 — 20은 과적합이었다.**

| 에폭 | 학습 손실 | 검증 Macro-F1 |
|---|---|---|
| 10 | 0.81 | **0.4991** |
| 20 | 0.06 | 0.4159 |

20에폭에서 학습 손실이 0.06까지 떨어지는 동안 검증 점수는 오히려 내려갔다.
80건을 암기해 처음 보는 대본에 못 쓰는 상태다. 1~5에폭 구간은 Macro-F1 0.077로
멈춰 있어(아직 학습 전) 10 미만도 부족하다.

## 5. 512토큰 제약 처리

대본이 klue/roberta의 입력 상한 512토큰을 넘는다. 실측 분포는 다음과 같다.

| | 중앙값 | 최대 | 512 초과 | 초과분 평균 |
|---|---|---|---|---|
| 원본 | 514 | 663 | 51건 | 64토큰 |
| 인사말 제거 후 | 458 | 595 | 23건 | 42토큰 |

**대응: 정형 인사말 제거 후 앞에서부터 512토큰 사용** (`preprocess.py`).
도입 인사("○○상담센터입니다")와 마무리 인사("감사합니다")만 지운다. 글자 수 제한
(앞 80자·뒤 90자 미만)을 둬서 **실질 내용과 인사가 한 줄에 섞인 경우는 남긴다.**

이 규칙으로 학습 80건 중 20건, 검증 20건 중 3건(`v2-041`, `scn-105`, `scn-088`)이 잘린다.
잘리는 부분은 대부분 종료 발화지만 실질 답변이 섞인 건도 있어 손실이 0은 아니다.

> `preprocess.py`는 **학습과 추론이 공유해야 한다.** 서비스(`predict`) 구현 시 이 모듈을
> import 한다. 복사해 쓰면 전처리가 갈려 조용히 틀린다.

검토했으나 채택하지 않은 대안:
- **KoBigBird**(4096토큰, 잘림 0) — 100건 규모에서 큰 모델은 손해가 클 것으로 판단. `--model`로 비교 가능
- **슬라이딩 윈도우** — 뒷조각에 분류 단서가 없어 틀린 라벨을 학습시킬 위험
- **위치 임베딩 확장** — 확장분을 학습시킬 데이터가 없음

## 6. 평가 규칙

**최종 점수는 마지막 에폭 모델을 쓴다.** 에폭마다 재서 제일 높은 값을 고르면(early stopping)
검증 20건에 맞춘 점수가 되어 실력이 부풀려진다. 에폭별 점수는 참고용으로만 기록한다.

**단일 실행 결과로 모델을 비교하지 않는다.** 검증 20건은 클래스당 2~6건뿐이라
1건 차이가 Macro-F1을 크게 움직인다. 실제로 20에폭 실행 중 검증 점수가 에폭마다
0.42~0.59로 진동했다. 비교 시 seed 3개 이상의 평균과 편차를 함께 본다.

`eval/run.py`는 `analyze()` 파이프라인 전체를 채점하는 별개 도구다.
이 스크립트는 파이프라인에 붙기 전 **모델 자체**를 채점한다.
