## 1. 결과 요약

**Macro-F1 0.4637 ± 0.0251** (seed 3회 평균, 목표 0.85 미달)

| seed | Macro-F1 | Accuracy |
|---|---|---|
| 42 | 0.4991 | 0.50 |
| 7 | 0.4429 | 0.45 |
| 2026 | 0.4492 | 0.50 |
| **평균** | **0.4637** | 0.4833 |
| 표준편차 | 0.0251 | — |

목표는 명세 7장의 **Macro-F1 ≥ 0.85**다. 크게 미달이며, **원인은 모델이 아니라 데이터 부족**이다.
학습 데이터가 80건, 클래스당 7~25건뿐이다. 이 규모에서 0.46은 예상 범위 안이며
(6클래스 무작위 추측이 약 0.17), 실데이터 투입 시 개선을 기대한다.

seed를 바꿔도 편차가 ±0.025로 작다. 즉 **0.46은 운이 아니라 이 데이터로 낼 수 있는 실력**이고,
목표와의 격차도 재현성 있게 확인된 값이다.

## 2. 재현 방법

```bash
cd ai
uv sync --extra train                                    # torch·transformers·sklearn

uv run --extra train python train/split_data.py          # 골든셋 100건 → 학습 80 / 검증 20
uv run --extra train python train/train_category.py      # 학습·채점·저장 (seed 42)

# seed 3회 (위 결과표 재현)
for s in 42 7 2026; do
  uv run --extra train python train/train_category.py --seed $s
done
```

산출물은 `ai/data/` 아래라 커밋되지 않는다. 위 명령으로 재현한다.
- 분할: `data/scenarios/train.jsonl`, `data/scenarios/val.jsonl`
- 모델·지표: `data/models/category-{모델}-seed{시드}/` (`metrics.json`에 설정·에폭별 이력·최종 점수)

> 저장 경로에 에폭이 들어가지 않는다. **에폭만 바꿔 돌리면 앞 결과를 덮어쓴다.**
> 모델·seed를 바꾸는 비교는 경로가 갈리므로 안전하다.

## 3. 데이터

`data/scenarios/golden_category.jsonl` 100건. FAQ 333건에서 생성한 상담 시나리오를
Claude·Gemini 독립 라벨링으로 교차검증하고 불일치분을 사람이 판정한 골든셋이다
(사람 검수 26건 + AI 일치 74건). 생성 경위는 `ai/eval/` 참고.

계층 분할(stratified split)로 학습 80 / 검증 20을 나눈다. 무작위로 나누면 최소 클래스
(부정사용 9건)가 검증셋에 0건 들어가 F1 계산이 불가능해진다.

## 4. 설정값과 근거

| 인자 | 기본값 | 근거 |
|---|---|---|
| `--model` | `klue/roberta-base` | 명세 8.2·Step 3. KLUE 벤치마크에서 안정적 |
| `--seed` | 42 | 재현성. 여러 개로 돌려 편차 측정 |
| `--max-length` | 512 | roberta 구조상 상한 |
| `--epochs` | 10 | 아래 실측 |
| `--lr` | 2e-5 | 이 계열 관례값 |
| `--batch-size` | 8 | 80건 기준 1에폭 = 10스텝 |

디바이스는 MPS(Apple Silicon), fp32. MPS에서 fp16은 불안정하다(명세 11장).

**에폭 10의 근거 — 20은 과적합이었다.**

| 에폭 | 학습 손실 | 검증 Macro-F1 |
|---|---|---|
| 10 | 0.81 | **0.4991** |
| 20 | 0.06 | 0.4159 |

20에폭에서 학습 손실이 0.06까지 떨어지는 동안 검증 점수는 오히려 내려갔다.
80건을 암기해 처음 보는 대본에 못 쓰는 상태다. 1~5에폭 구간은 Macro-F1 0.077로
멈춰 있어(아직 학습 전) 10 미만도 부족하다.

## 5. 512토큰 제약 처리

대본이 klue/roberta의 입력 상한 512토큰을 넘는다. 실측 분포는 다음과 같다.

| | 중앙값 | 최대 | 512 초과 | 초과분 평균 |
|---|---|---|---|---|
| 원본 | 514 | 663 | 51건 | 64토큰 |
| 인사말 제거 후 | 458 | 595 | 23건 | 42토큰 |

**대응: 정형 인사말 제거 후 앞에서부터 512토큰 사용** (`preprocess.py`).
도입 인사("○○상담센터입니다")와 마무리 인사("감사합니다")만 지운다. 글자 수 제한
(앞 80자·뒤 90자 미만)을 둬서 **실질 내용과 인사가 한 줄에 섞인 경우는 남긴다.**

이 규칙으로 학습 80건 중 20건, 검증 20건 중 3건(`v2-041`, `scn-105`, `scn-088`)이 잘린다.
잘리는 부분은 대부분 종료 발화지만 실질 답변이 섞인 건도 있어 손실이 0은 아니다.

> `preprocess.py`는 **학습과 추론이 공유해야 한다.** 서비스(`predict`) 구현 시 이 모듈을
> import 한다. 복사해 쓰면 전처리가 갈려 조용히 틀린다.

검토했으나 채택하지 않은 대안:
- **KoBigBird**(4096토큰, 잘림 0) — 100건 규모에서 큰 모델은 손해가 클 것으로 판단. `--model`로 비교 가능
- **슬라이딩 윈도우** — 뒷조각에 분류 단서가 없어 틀린 라벨을 학습시킬 위험
- **위치 임베딩 확장** — 확장분을 학습시킬 데이터가 없음

## 6. 평가 규칙

**최종 점수는 마지막 에폭 모델을 쓴다.** 에폭마다 재서 제일 높은 값을 고르면(early stopping)
검증 20건에 맞춘 점수가 되어 실력이 부풀려진다. 에폭별 점수는 참고용으로만 기록한다.

**단일 실행 결과로 모델을 비교하지 않는다.** 검증 20건은 클래스당 2~6건뿐이라
1건 차이가 Macro-F1을 크게 움직인다. 실제로 20에폭 실행 중 검증 점수가 에폭마다
0.42~0.59로 진동했다. 비교 시 seed 3개 이상의 평균과 편차를 함께 본다.

`eval/run.py`는 `analyze()` 파이프라인 전체를 채점하는 별개 도구다.
이 스크립트는 파이프라인에 붙기 전 **모델 자체**를 채점한다.
