# SR유형 분류 모델 (B안) — 개요

상담 통화(STT+화자분리 전문)를 입력받아 **SR유형 8종** 중 하나로 분류하는 모델.
상담사의 후처리(접수 분류) 작업을 자동화하는 것이 목적이다. 소유: 이재혁.

관련 문서: [label_definition.md](label_definition.md)(라벨 정의) ·
[data_generation.md](data_generation.md)(데이터 생성 과정) ·
[training_guide.md](training_guide.md)(실행 가이드)

---

## 1. 목적

콜센터 상담원이 통화 후 SR(Service Request)유형을 수기로 분류해 접수하는 작업을
모델이 대신 판정하도록 하는 것. 오분류의 실제 비용은 **적기처리기간(SLA) 위반**이므로,
단순 정확도가 아니라 "SLA가 긴 건을 놓치지 않는가"를 핵심 지표로 삼는다.

## 2. 라벨 8종

| SR유형 | 적기처리기간 | 축약 우선순위 |
|---|---:|---:|
| 시스템오류 | 30일 | 1 (최상위) |
| 기능개선 | 30일 | 2 |
| 자료보정 | 5일 | 3 |
| 정책 및 지침문의 | 5일 | 4 |
| 고객PC환경 | 3일 | 5 |
| 기타 | 3일 | 6 |
| 자료확인 | 2일 | 7 |
| 사용법문의 | 1일 | 8 (최하위) |

한 통화에 여러 유형이 섞일 수 있어 **멀티라벨**로 학습하고, 서빙 시엔 "적기처리기간이
긴 유형을 우선한다"는 기관 참고자료 규칙으로 최종 유형 1개로 축약한다(`collapse_probs`).
동점 tie-break(예: 시스템오류 vs 기능개선 둘 다 30일)는 정의서 §1.1에서 별도로 확정.

## 3. 모델 구조

- **백본**: `klue/roberta-base` (한국어 사전학습 RoBERTa). 데이터가 늘면 `roberta-large`로 전환 예정.
- **화자 구분**: 발화마다 `[상담사]`/`[고객]` 스페셜 토큰을 붙이고, 토큰별 화자 id를 워드
  임베딩에 더하는 화자 임베딩을 추가(0으로 초기화해 학습 초반엔 영향 없이 시작).
- **풀링**: CLS 토큰 + 평균 풀링 결합(`cls_mean`).
- **헤드**: Dropout → `Linear(hidden×2, 8)` → 클래스별 독립 시그모이드(멀티라벨).
- **길이 처리**: 512토큰 초과 시 앞·뒤를 잘라 붙이는 head+tail truncation.

## 4. 학습 방법

**순수 PyTorch 루프**로 구현(HF Trainer 미사용, GPU 가속 요건).

- **손실**: `BCEWithLogitsLoss` + `pos_weight`(우선순위 가중 × 클래스불균형 보정의 곱).
  두 가중치를 곱하면 결합값이 과도하게 벌어져 여러 클래스가 동시에 임계값을 넘고
  축약 규칙이 매번 최상위 클래스로 뭉개버리는 문제가 있었다(1차 실행에서 실제로 발생,
  아래 5절 참고) — 가중치 상한을 낮춰 해결.
- **옵티마이저**: AdamW + 계층별 학습률 감쇠(LLRD, 하위 레이어일수록 학습률 낮게).
- **정밀도**: bf16 autocast + TF32 matmul (RTX 4080 SUPER).
- 선형 warmup 스케줄러, gradient clipping, 동적 패딩, 에폭별 조기종료(patience).
- 검증 지표는 **축약 전(8헤드 독립) macro-F1**과 **축약 후(최종 SR유형) macro-F1**을
  동시에 기록 — 축약 규칙 때문에 지표가 정체된 것처럼 보이는 상황과 실제 학습 정체를
  구분하기 위함.
- **STT 노이즈 증강**: 실제 서빙 입력(STT+화자분리 결과)과의 간극을 메우기 위해, 학습
  배치를 만들 때마다 필러어·ASR 용어 오인식·조사 탈락·숫자 표기 붕괴·화자분리 뒤바뀜을
  확률적으로 주입.

## 5. 데이터

실데이터는 가명처리 대기 중이라, **라벨 조건부 합성 생성**으로 1차 학습셋을 만들었다
(자세한 과정은 [data_generation.md](data_generation.md)).

- 목표 SR유형을 먼저 고정하고 대화를 생성하는 방식으로 라벨 노이즈를 원천 차단.
- 생성 격자: SR유형(7) × 업무소분류(29) × 난이도(일반/경계/복합), 정의서의 혼동쌍 5종을
  경계 난이도에 반영.
- 1차 직접 생성분(60건)은 TF-IDF 진단에서 macro-F1 1.000(표현 정형화 적신호)이 나와 폐기.
- 컨텍스트를 공유하지 않는 서브에이전트 4개로 재생성(112건) → 진단 macro-F1 0.6375(정상
  범위)로 최종 채택.
- **최종 규모: 학습 98건 / 검증 14건** (8종 라벨 전부 존재, 소분류 29종 전부 커버).

## 7. 현재 상태 / 한계

- **스모크 규모다.** 검증 14건, 클래스당 positive 7~23건 수준이라 위 지표는 파이프라인이
  정상 작동함을 보여주는 것이지 실전 성능 추정치가 아니다. 실데이터 확보 후 재학습 필요.
- **임계값 미보정.** 현재 `thresholds`는 전부 0.5(기본값). P5 캘리브레이션
  (`callwrap.calibrate`, SLA위반 페널티 목적함수)을 아직 안 돌렸다.
- **서비스 배포 전.** `callwrap_ai.sr_type`에 로딩 로직은 연동돼 있으나(코드 계약 테스트
  통과 확인), 실제 체크포인트 파일은 서빙 경로(`data/models/sr-type-klue-roberta-base-v2/`)에
  아직 배치되지 않았다 — 배치 전까지 SR유형 필드는 부분 실패(`classify_type`)로 빠진다.
