# SR유형 라벨 정의서 (v1.0)

- **대상 과제**: 사회서비스 전자바우처 상담센터 상담 후처리 자동화 (CallWrap) 중 **B안 — SR유형 분류**
- **출처**: `99_archive/산학협력 프로젝트 과제4_상담음성 데이터 AI분석요약_참고자료.xlsx` (SR유형 / 적기처리기간 시트)
- **입력**: STT + 화자분리된 상담 통화 전문
- **출력**: SR유형 8종 중 1종 (내부적으로는 멀티라벨 → 우선순위 축약)
- **범위 밖**: 업무 대/중/소분류(A안), 상담등급(일반/악성/칭찬) — 별도 과제

## 1. 라벨 체계

| # | SR유형 | 적기처리기간 | 우선순위 | 한 줄 정의 |
|---|--------|---------|:---:|------|
| 1 | 시스템오류 | 30일 | 1 | 시스템이 설계대로 동작하지 않음 (오류·미동작·계산 이상) |
| 2 | 기능개선 | 30일 | 2 | 시스템은 정상 동작하나 없는 기능/불편 개선 요청 |
| 3 | 자료보정 | 5일 | 3 | 등록된 데이터의 **변경·정정·취소** 요청 |
| 4 | 정책 및 지침문의 | 5일 | 4 | 제도·규정·기준의 해석 문의 |
| 5 | 고객PC환경 | 3일 | 5 | 원인이 사용자 단말/네트워크/주변기기 |
| 6 | 자료확인 | 2일 | 6 | 데이터 **조회·확인** 요청 (변경 없음) |
| 7 | 사용법문의 | 1일 | 7 | 시스템 조작 방법 안내로 종결 |
| 8 | 기타 | 3일 | 8 | 위 어디에도 속하지 않음 (fallback) |

### 1.1 우선순위 산정 근거

참고자료 명시 규칙:

> **“SR유형 설정은 적기처리기간이 긴 항목을 우선하여 설정”**

적기처리기간만으로는 3쌍이 동점이므로 아래 tie-break를 **본 정의서에서 확정**한다.

| 동점 | 결정 | 근거 |
|---|---|---|
| 시스템오류(30) vs 기능개선(30) | **시스템오류 우선** | 오류는 현재 업무가 중단된 상태, 개선은 요구사항 접수. 업무 영향도가 더 큼 |
| 자료보정(5) vs 정책문의(5) | **자료보정 우선** | 보정은 실제 데이터 변경 작업(쓰기)이 발생. 처리 산출물이 존재 |
| 고객PC환경(3) vs 기타(3) | **고객PC환경 우선** | `기타`는 정의상 최하위 fallback이며 어떤 경우에도 다른 유형을 이기지 않는다 |

**최종 우선순위 (높음 → 낮음)**

```
시스템오류 > 기능개선 > 자료보정 > 정책 및 지침문의 > 고객PC환경 > 자료확인 > 사용법문의 > 기타
```

### 1.2 비대칭 오류비용

“긴 쪽 우선” 규칙은 **보수적 편향**을 의도한 것이다.

- 실제 `시스템오류`(30일)를 `사용법문의`(1일)로 예측 → **SLA 위반**. 업무 손실 발생.
- 실제 `사용법문의`(1일)를 `시스템오류`(30일)로 예측 → 여유 기한 배정. 손실 작음.

따라서 학습·평가 모두에서 **우선순위 상위 클래스의 재현율(recall)을 우선**한다.
- 학습: BCE `pos_weight`를 상위 클래스에 가중
- 추론: 상위 클래스 임계값을 낮게(민감하게) 캘리브레이션
- 평가: macro-F1과 함께 **SLA 위반율**을 별도 추적

## 2. 라벨링 원칙

### 원칙 1 — 멀티라벨로 표기하고 규칙으로 축약한다

한 통화에는 여러 유형이 섞이는 것이 정상이다.

> 고객: “결제 버튼을 눌러도 반응이 없어요” → (시스템오류)
> 상담사: “그 화면은 여기로 들어가셔야 합니다” → (사용법문의)

**표기 방식**: 대화에 존재하는 **모든** 유형에 1을 표기한다.
**최종 SR유형**: 표기된 유형 중 §1.1 우선순위 최상위를 선택한다.

이유:
- 단일 라벨로만 표기하면 부차 유형의 언어 신호가 전부 노이즈가 된다.
- 축약 규칙이 코드로 100% 재현되므로, 적기처리기간이 개정되어도 **재학습 없이 후처리만 수정**하면 된다.

### 원칙 2 — “원인”이 아니라 “처리 부서/처리 성격”으로 판정한다

SR유형은 상담 주제가 아니라 **이 건이 어디로 가서 어떻게 처리되는가**를 나타낸다.
결제 관련 문의라도 → 조작 안내면 `사용법문의`, 데이터 정정이면 `자료보정`, 서버 장애면 `시스템오류`.

### 원칙 3 — 판정 근거는 상담사 발화에서도 찾는다

고객 발화만으로는 모호한 경우가 많다. 상담사의 확인 질문과 처리 결론이 결정적 신호다.

- “다른 PC에서도 그러신가요?” → 고객PC환경 vs 시스템오류 분기 신호
- “제가 조회해서 알려드릴게요” → 자료확인
- “정정 요청 접수해서 처리해 드리겠습니다” → 자료보정
- “개발팀에 전달하겠습니다” → 시스템오류 또는 기능개선

### 원칙 4 — `기타`는 최후의 선택이다

다른 7개 중 하나로 판정 가능하면 절대 `기타`를 쓰지 않는다.
`기타`가 정당한 경우: 오접·잘못 걸린 전화, 타 기관 소관 문의, 단순 인사/확인, 상담 내용 판별 불가.

## 3. 유형별 정의 카드

### 3.1 시스템오류 (30일) — 우선순위 1

**정의**: 사용자가 정상 경로로 조작했음에도 시스템이 설계된 대로 동작하지 않는 상태.

**포함**
- 오류 메시지 발생, 화면 멈춤/백지, 무한 로딩
- 버튼·링크 미동작, 저장/전송 실패
- 계산 결과 이상 (결제금액·본인부담금·가산단가 산정 오류)
- 데이터 미반영/누락 (등록했는데 목록에 없음)
- 연계 실패 (행복e음 연계 오류, 결제단말기 승인 불가)
- 특정 사용자만이 아니라 **재현되는** 문제

**제외**
- 사용자 단말에서만 발생 → `고객PC환경`
- 조작 방법을 몰라서 안 된 것 → `사용법문의`
- 설계대로 동작하나 불편 → `기능개선`
- 입력값이 잘못되어 결과가 틀린 것 → `자료보정`

**대표 신호**: “오류가 떠요”, “먹통이에요”, “아무 반응이 없어요”, “금액이 이상하게 나와요”, “저장이 안 돼요”, “계속 튕겨요”, (상담사) “개발팀에 확인 요청 드리겠습니다”, “장애 접수해 드릴게요”

---

### 3.2 기능개선 (30일) — 우선순위 2

**정의**: 시스템은 현재 스펙대로 정상 동작하지만, 없는 기능의 추가나 사용성 개선을 요청.

**포함**
- 신규 기능 요청 (“엑셀 다운로드 되게 해주세요”)
- 화면/항목 추가 요청 (“목록에 담당자 컬럼도 나오게 해주세요”)
- 처리 절차 간소화 요청, 일괄 처리 요청
- 제약 완화 요청 (“한 번에 100건만 되는데 늘려주세요”)

**제외**
- 기능은 있는데 못 찾은 것 → `사용법문의`
- 기능이 있는데 동작을 안 하는 것 → `시스템오류`

**대표 신호**: “~기능이 있으면 좋겠어요”, “~하게 바꿔주실 수 없나요”, “왜 이건 안 되게 해놨나요”, (상담사) “요청사항으로 접수해서 개선 검토하겠습니다”

---

### 3.3 자료보정 (5일) — 우선순위 3

**정의**: 이미 등록된 데이터의 변경·정정·삭제·취소를 요청. **쓰기 작업이 발생**한다.

**포함**
- 잘못 입력된 값 정정 (대상자 정보, 제공인력 정보, 급여 등록 내역)
- 과오결제 취소/정정, 예외적 결제 처리
- 자격 정보 정정, 바우처 생성/삭제 요청
- 본인부담금 입금액 정정·환급 처리
- 기간 경과 건의 소급 처리 요청

**제외**
- 조회만 하고 끝 → `자료확인`
- 사용자가 화면에서 직접 수정 가능하고 방법만 안내 → `사용법문의`
- 시스템이 막아서 수정이 안 되는 것 → `시스템오류`

**대표 신호**: “잘못 등록했는데 고쳐주세요”, “취소해 주세요”, “다시 넣어주세요”, “삭제 부탁드립니다”, (상담사) “정정 요청 접수하겠습니다”, “보정 처리해 드리겠습니다”

---

### 3.4 정책 및 지침문의 (5일) — 우선순위 4

**정의**: 제도·규정·기준에 대한 해석 문의. 답이 **시스템 조작이 아니라 규정**이다.

**포함**
- 자격 요건, 신청 기준 및 절차 (제도적 기준)
- 본인부담금 산정 기준, 면제·경감 대상 여부
- 가산단가 적용 요건, 서비스 비용 지급 기준
- 부정사용 신고 대상/절차/포상금 기준
- 제공기관·제공인력 자격 및 교육 요건
- 지자체 사업 운영 지침, 예탁금 관리 기준

**제외**
- 답이 “화면에서 이렇게 하세요”이면 → `사용법문의`
- 특정 건의 데이터가 기준에 맞는지 조회 요청 → `자료확인`

**대표 신호**: “~한 경우에도 되나요?”, “기준이 어떻게 되나요?”, “규정상 가능한가요?”, “며칠 이내에 해야 하나요?”, (상담사) “지침상으로는~”, “고시에 따르면~”

---

### 3.5 고객PC환경 (3일) — 우선순위 5

**정의**: 문제의 원인이 시스템이 아니라 사용자 측 단말/환경.

**포함**
- 브라우저 종류·버전 문제, 호환성 보기, 캐시/쿠키
- 공동인증서(공인인증서) 설치·인식·만료 문제
- 보안 프로그램(키보드보안, 방화벽, 백신) 충돌
- OS/Java/액티브X 등 실행환경
- 팝업 차단, 인쇄/스캔 장치 문제
- **결제단말기·지문인식기 등 주변기기 인식 불가**
- 네트워크 단절, 사내망 차단

**제외**
- 다른 PC/브라우저에서도 동일하게 재현 → `시스템오류`

**대표 신호**: “인증서가 안 잡혀요”, “지문인식기가 인식이 안 돼요”, “단말기에 오류가 떠요”, “설치가 안 돼요”, (상담사) “크롬 말고 엣지로 접속해 보시겠어요?”, “보안프로그램 재설치해 보세요”, “다른 컴퓨터에서도 그러신가요?”

---

### 3.6 자료확인 (2일) — 우선순위 6

**정의**: 등록된 데이터의 조회·확인 요청. **읽기 전용, 변경 없음.**

**포함**
- 결제 내역·지급 내역 조회
- 대상자 자격 유효기간·상태 확인
- 바우처 잔액·생성 여부 확인
- 처리 진행상황 확인 (“접수된 건 어떻게 됐나요?”)
- 제공인력 등록 여부 확인

**제외**
- 확인 결과 값이 틀려서 정정까지 요청 → `자료보정`
- 사용자가 직접 조회하는 방법 안내로 종결 → `사용법문의`

**대표 신호**: “확인 좀 부탁드려요”, “조회해 주실 수 있나요?”, “언제까지인지 알려주세요”, “얼마 남았나요?”, (상담사) “제가 조회해 드리겠습니다”, “확인해 보니 ~로 되어 있습니다”

---

### 3.7 사용법문의 (1일) — 우선순위 7

**정의**: 시스템은 정상이고, 조작 방법을 몰라서 발생한 문의. **안내로 즉시 종결.**

**포함**
- 메뉴 위치·화면 경로 문의
- 입력 항목 의미·작성 방법
- 등록/신청/결제 절차의 조작 순서
- 조회 조건 설정 방법, 출력·인쇄 방법

**제외**
- 절차의 **제도적 요건**을 묻는 것 → `정책 및 지침문의`
- 시키는 대로 했는데 안 되는 것 → `시스템오류`
- 그 기능 자체가 없는 것 → `기능개선`

**대표 신호**: “어디서 하나요?”, “어떻게 등록해요?”, “메뉴가 어디 있어요?”, “이 항목은 뭘 넣어야 하나요?”, (상담사) “좌측 메뉴에서 ~ 선택하시고”, “화면 상단 ~ 버튼을 누르시면 됩니다”

---

### 3.8 기타 (3일) — 우선순위 8 (fallback)

**정의**: 다른 7개 유형 중 어디에도 해당하지 않는 건.

**포함**
- 오접, 잘못 걸린 전화
- 타 기관 소관 문의 (관할 안내 후 종결)
- 단순 인사·확인·감사 통화
- 통화 품질/중단으로 상담 내용 판별 불가
- 상담센터 운영시간·연락처 문의

**제외**: 다른 유형으로 판정 **가능한 모든 경우**

## 4. 혼동쌍 판정 규칙

모델 성능은 아래 5개 경계에서 갈린다. 생성·검수 시 반드시 이 규칙을 적용한다.

### C1. 시스템오류 ↔ 고객PC환경 (최대 혼동쌍)

**핵심 질문: 다른 환경에서도 재현되는가?**

| 관찰 | 판정 |
|---|---|
| 다른 PC/브라우저/사용자에게서도 동일 발생 | 시스템오류 |
| 특정 단말에서만 발생 | 고객PC환경 |
| 인증서·보안모듈·주변기기(지문인식기, 결제단말기) 관련 | 고객PC환경 |
| 서버 응답 오류코드, 전체 사용자 영향, 계산 결과 이상 | 시스템오류 |
| 상담사가 브라우저 변경/재설치를 안내하고 해결됨 | 고객PC환경 |
| 상담사가 개발팀 이관·장애 접수를 언급 | 시스템오류 |

**미확인 시**: 상담사가 환경을 확인하지 않고 종료했다면 **시스템오류**(우선순위 상위)로 판정한다.

---

### C2. 시스템오류 ↔ 사용법문의

**핵심 질문: 정상 경로로 조작했는데 실패했는가, 경로를 몰랐는가?**

| 관찰 | 판정 |
|---|---|
| 상담사 안내대로 하니 정상 동작 | 사용법문의 |
| 안내대로 했는데도 실패 | 시스템오류 |
| 고객이 올바른 화면에서 오류 메시지를 본 상태 | 시스템오류 |
| 고객이 잘못된 메뉴에 있었음 | 사용법문의 |

---

### C3. 자료확인 ↔ 자료보정

**핵심 질문: 데이터 변경이 발생했는가?**

| 관찰 | 판정 |
|---|---|
| 조회 결과를 알려주고 종료 | 자료확인 |
| 조회 후 값이 틀려 정정 요청/접수 | **자료보정** (멀티라벨: 자료확인+자료보정 → 자료보정) |
| 삭제·취소·재등록 요청 | 자료보정 |
| “언제까지인가요” “얼마인가요” 류 | 자료확인 |

---

### C4. 정책 및 지침문의 ↔ 사용법문의

**핵심 질문: 답이 “규정/기준”인가 “화면 조작 순서”인가?**

| 관찰 | 판정 |
|---|---|
| 상담사 답변이 요건·기준·기한·대상 여부 | 정책 및 지침문의 |
| 상담사 답변이 메뉴 경로·버튼·입력 방법 | 사용법문의 |
| “신청 어떻게 해요?” → 자격 요건 설명 | 정책 및 지침문의 |
| “신청 어떻게 해요?” → 화면 조작 안내 | 사용법문의 |

> `신청기준및절차` 소분류는 두 유형에 모두 걸친다. **답변 내용**으로 판정한다.

---

### C5. 기능개선 ↔ 시스템오류

**핵심 질문: 설계된 대로 동작하고 있는가?**

| 관찰 | 판정 |
|---|---|
| 원래 그런 기능이 없음 | 기능개선 |
| 있는 기능이 동작하지 않음 | 시스템오류 |
| 제약이 의도된 정책 (예: 월 1회 제한) | 정책 및 지침문의 또는 기능개선 |
| 동작은 하는데 느리거나 불편 | 기능개선 |
| 동작 결과가 틀림 | 시스템오류 |

## 5. 판정 절차 (라벨러/검수자용)

1. 통화 전체를 읽고 **고객의 최초 용건**과 **상담사의 처리 결론**을 표시한다.
2. 3장 정의 카드 기준으로 **해당하는 모든 유형**에 체크한다 (멀티라벨).
3. 경계 사례는 4장 혼동쌍 규칙을 적용한다.
4. 체크된 유형 중 §1.1 우선순위 최상위를 **최종 SR유형**으로 확정한다.
5. 아무것도 체크되지 않으면 `기타`.
6. 판정 근거가 된 발화 인덱스를 함께 기록한다 (검수·오답분석용).

```
[예시]
고객: 결제가 자꾸 실패해요                     → 시스템오류?
상담사: 혹시 지문인식기 인식은 되시나요?
고객: 아 그건 빨간불이 계속 떠 있어요          → 고객PC환경 ✔
상담사: 드라이버 재설치 안내드릴게요
고객: 그리고 지난달 결제내역도 확인 부탁드려요  → 자료확인 ✔

멀티라벨: {고객PC환경, 자료확인}
우선순위: 고객PC환경(5) > 자료확인(6)
최종 SR유형: 고객PC환경
```

## 6. 데이터 생성·검수 기준 (P2 게이트)

### 6.1 생성 시 필수 조건
- 라벨을 **먼저** 지정하고 그 조건에 맞는 대화를 생성한다 (label-first).
- 생성 격자: `SR유형(8) × 업무소분류(29) × 난이도(일반/경계/복합)`
- 4장 혼동쌍 5종은 **의도적으로 별도 물량**을 배정한다.
- 복합 대화(2개 이상 유형 실제 포함) 비율 20~30%.

### 6.2 검수 통과 기준
파일럿 200건에 대해 사람이 3장·4장 기준으로 재라벨링했을 때:

| 항목 | 기준 |
|---|---|
| 최종 SR유형 일치율 | **≥ 95%** |
| 멀티라벨 Jaccard 유사도 | ≥ 0.85 |
| 혼동쌍 케이스가 실제로 경계에 위치 | 육안 확인 |
| 유형별 정형 표현 반복 (예: 모든 시스템오류가 “시스템 오류가 발생하여”로 시작) | **없을 것** |

**미달 시**: 본 정의서 또는 생성 프롬프트를 수정하고 파일럿을 재실행한다. 본 생성으로 넘어가지 않는다.

### 6.3 품질 진단 신호
TF-IDF 베이스라인이 합성 검증셋에서 **macro-F1 0.90을 초과**하면, 이는 좋은 신호가 아니라 **표현 다양성 부족**의 신호다. 6.1로 회귀한다.
