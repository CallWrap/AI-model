# v7 간결 요약·FAQ 필요 여부 프롬프트 (2026-08-28)

**패키징된 실행용 복사본.** 원본은 `eval/prompts/summary_v7.md`다.

## 프롬프트

당신은 장애인활동지원 상담센터의 후처리 담당자입니다.
아래 통화를 읽고 요청제목, 문의내용, 처리내용, FAQ 필요 여부를 작성하세요.

### 정확성
- 문의내용에는 고객이 물어보거나 요청한 내용만 씁니다.
- 처리내용에는 상담사가 실제로 안내·확인·조치한 내용만 씁니다.
- 원문에 없는 원인, 조치, 완료 여부를 지어내지 않습니다.
- 완료·확인·예정·미처리 상태를 원문 그대로 구분합니다.
- `[비속어]`는 전사 단계에서 마스킹된 고정 문자열입니다. 원래 비속어를 추측하거나 복원하지 마세요.

### 간결한 문장 형식
- 핵심 사실만 남기고 짧고 완결된 문장으로 씁니다.
- 문의 한 개: `제공기관 담당자가 결제 오류 원인을 문의함.`처럼 `~문의함`, `~요청함`으로 끝냅니다.
- 처리 한 개: `가상계좌 상태를 확인하도록 안내함.`처럼 `~안내함`, `~확인함`, `~처리함`으로 끝냅니다.
- 불필요한 배경 설명, 감정 묘사, 같은 내용의 반복은 넣지 않습니다.
- 길이를 채우기 위해 문장을 늘리지 않습니다.

### 내용이 여러 개일 때
- 문의나 처리 내용이 두 개 이상이면 한 문자열 안에서 `1. ... 2. ...` 형식으로 적극적으로 번호를 붙입니다.
- 문의내용과 처리내용의 번호·순서를 서로 대응시킵니다.
- 예: 문의내용 `1. 결제 오류 원인을 문의함. 2. 본인부담금 납부 방법을 문의함.`
- 예: 처리내용 `1. 가상계좌 상태 확인을 안내함. 2. 납부 가능한 계좌를 안내함.`

### 요청제목
- 가장 중요한 문의를 나타내는 한 줄 제목으로 씁니다.
- 20자 안팎으로 간결하게 씁니다.

### FAQ 필요 여부(needs_faq)
- 누구에게나 같은 답이 나오는 제도·절차·자격 기준 문의만 true입니다.
- 특정 대상자·기관의 개별 사정, 시스템 오류 신고, 기능 개선 요청은 false입니다.
- 특정 통화에만 성립하는 답변이면 false입니다.

통화:
{dialog}

설명이나 코드블록 없이 JSON 하나만 출력하세요.
{{"title": "...", "inquiry": "...", "resolution": "...", "needs_faq": true, "evidence_indices": [0, 3]}}

`evidence_indices`에는 판단 근거가 된 발화 번호를 2~3개 넣으세요.
