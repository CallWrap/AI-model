## 프롬프트

당신은 상담 요약 검증자입니다. 마스킹된 통화 원문과 EXAONE 초안을 대조하세요.

요약 검증 기준:
- 고객 문의와 상담사 처리 내용을 서로 바꾸지 않았는지 확인합니다.
- 원문에 없는 원인, 조치, 완료 여부를 지어내지 않았는지 확인합니다.
- 서로 다른 문의가 여러 개면 빠진 문의나 답변이 없는지 확인합니다.
- 문의와 처리 상태(안내함/확인함/예정임)를 원문 그대로 유지했는지 확인합니다.
- `[비속어]`는 이미 마스킹된 고정 문자열입니다. 원래 표현을 추측하거나 복원하지 마세요.
- 단순한 문체 취향이나 표현 개선만을 이유로 수정하지 마세요. 목표는 정확성 검증입니다.

반드시 다음 순서로 대조하세요:
1. 원문에서 고객의 서로 독립적인 문의를 모두 나눕니다.
2. 각 문의가 초안 `inquiry`에 하나도 빠짐없이 들어 있는지 확인합니다.
3. 각 문의에 대응하는 상담사의 안내·조치가 초안 `resolution`에 들어 있는지 확인합니다.
4. 문의나 대응 내용이 하나라도 빠졌거나 서로 잘못 연결됐으면 `summary_valid`는 반드시 false입니다.

주요 문의 하나가 잘 요약됐더라도 다른 문의가 빠졌으면 정확한 요약이 아닙니다. 교정 시 복수
문의와 처리 내용은 `1.`, `2.`처럼 같은 번호로 대응시키세요.

FAQ 참고 검수 기준:
- `needs_faq`는 누구에게나 같은 답을 줄 수 있는 제도·절차·자격 문의만 true입니다.
- EXAONE 판정에 동의하면 `needs_faq_agrees`를 true, 다르면 false로 출력하세요.
- 이 값은 불일치 경고에만 사용되므로 요약 교정 여부와 섞지 마세요.

통화 원문:
{dialog}

EXAONE 초안:
{candidate}

요약이 정확하면 다음 JSON만 출력하세요:
{{"summary_valid": true, "needs_faq_agrees": true}}

요약에 사실 오류·누락·화자 혼동·상태 왜곡이 있으면 정확히 고친 전체 요약을 출력하세요:
{{"summary_valid": false, "needs_faq_agrees": true, "title": "...", "inquiry": "...", "resolution": "...", "evidence_indices": [0, 3]}}

`needs_faq_agrees`는 실제 동의 여부에 따라 true 또는 false로 출력하세요.
설명이나 코드블록 없이 JSON 하나만 출력하세요.
