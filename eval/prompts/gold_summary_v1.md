# v1 요약 정답 재작성 프롬프트 (2026-08-18)

Claude Opus에게 **이미 만들어진 대본을 읽고** 후처리 폼 정답을 다시 작성하게 한다.

## 왜 다시 뽑나

기존 정답은 `scenario_v2.md`가 **요약과 대본을 한 응답에서 동시에** 생성한 것이다.
요약을 먼저 쓰고 대본을 이어 쓰다 보니, 대화가 계획과 다르게 흘러가면 앞서 쓴 요약이
어긋난 채 남는다.

실제 사례 — `sub-053`
```
대본     상담사: "정확한 잔여 한도는 본인 확인 후 안내드릴 수 있으니…"
         고객:   "지금은 대략적인 것만 알아도 될 것 같아요. 나중에 다시 전화드릴게요."
기존 정답 "이번 달 사용량과 잔여 한도를 조회해 안내하고…"   ← 조회하지 않았다
```
EXAONE 예측이 오히려 정확했다.

`needs_followup`도 같은 문제가 있다. 생성 스펙에서 `i % 10 in (0, 3, 7)`로 **순번에 따라
기계적으로 배정**됐고 내용을 보고 정한 값이 아니다.

**대본을 읽고 요약하면 구조적으로 불일치가 사라진다.** 이것이 모델을 키우는 것보다 중요하다.

## 사용

```
uv run python eval/regold_summary.py            # 전체
uv run python eval/regold_summary.py --limit 3  # 시험
```

결과는 기존 정답과 나란히 비교해 **크게 다른 건만 사람이 검수**한다 (명세 9.1).
LLM이 만든 정답으로 LLM을 평가하는 순환을 완전히 없애지는 못하므로,
차이가 큰 건은 사람 판정을 거친다.

## 프롬프트

당신은 장애인활동지원 상담센터의 후처리 담당자입니다.
아래 통화 **원문만 보고** 후처리 폼을 채우세요.

**원문에 없는 내용을 쓰지 마세요.** 상담사가 하지 않은 조치를 했다고 적으면 안 됩니다.
통화가 어떻게 끝났는지 마지막까지 읽고 판단하세요.

### 화자 구분
- `문의내용`: 고객이 물어본 것만. 상담사의 답변을 넣지 마세요.
- `처리내용`: 상담사가 답하거나 조치한 것만. 고객의 질문·반응을 넣지 마세요.

### 문의내용은 "누가"로 시작
`제공기관 담당자가` / `지자체 담당 공무원이` / `수급자 보호자가` 등으로 시작해
**누가 · 왜 · 무엇을** 순서로 서술합니다. 문의가 여러 개면 모두 담습니다.

### 분량
- 요청제목: 한 줄, 20자 안팎
- 문의내용: 2~3문장, 90자 안팎
- 처리내용: 2~3문장, 100자 안팎

문장 끝은 `~함`, `~요청함`, `~안내함`처럼 기록체로 맺습니다.

### needs_followup
**상담사 본인이 통화 뒤에 직접 할 일이 남았는가**로만 판단합니다.
- true: 상담사가 "확인 후 연락드리겠습니다", "담당 부서에 전달하겠습니다",
  "장애로 접수하겠습니다"라고 **원문에서 말했을 때**
- false: 통화 중 안내·확인·해결이 끝남. **고객에게 "지자체에 문의하세요",
  "기관에 연락하세요"라고 안내한 것은 false** — 상담사 일은 끝났습니다.
- 고객이 "나중에 다시 전화하겠다"고 한 것도 false입니다. 상담사 일이 아닙니다.

### needs_faq
**이 통화의 답변을 그대로 다른 사람에게 줄 수 있는가**로 판단합니다.
- true: 제도·절차·자격 기준처럼 누구에게나 같은 답
- false: 특정 대상자의 개별 사정, 시스템 오류 신고, 기능 개선 요청
